Case 01 · Linguistic Ethics

Fidelity vs. Standardization

Automated QA kept flagging dialect as error. I built the rules that tell a real mistake apart from a character's voice — without breaking glossary or locale compliance.

LocalizationSDHTerminology GovernanceError Analysis

Problem

MT and vendor style rules “corrected” regional speech into neutral English.

Characters lost their accent, brands got translated, EN-UK drifted into EN-US.

Solution

Added a Language/Local/Dialect category to the error taxonomy.

Locale-locked projects, whitelisted regional lexicon, protected named entities.

Every decision documented so vendors could act on it, not argue about it.

Before

“me grandfather” → “my grandfather”

“travelling” → “traveling”

“Product X Boards” → “Quadros do Produto X”

Identity flattened · brand broken

After

“me grandfather” — kept, tagged as dialect

“travelling” — EN-UK locked

“Product X Boards” — never translated

Voice preserved · glossary respected

Metrics

Dialect markers preserved after review100%
False MT corrections blocked before delivery320+
Terminology consistency across the title set98%
Vendor disputes resolved with documented evidenceAll

Case 02 · Accessibility

Language Is Access

Captions were treated as transcription. I moved accessibility upstream — sound events, speaker IDs and reading rate designed into the workflow, not patched at QA.

Inclusive CommunicationSDHAudio DescriptionProject Coordination

Problem

Generic “[music]” cues, missing speaker IDs, captions too dense to read.

Quality depended on whichever linguist was assigned to the title.

Solution

SDH style guide with sound-event, speaker-ID and CPS rules.

Audio description scripting and QA checklists shared across vendors.

Delivery coordination across concurrent titles in PT-BR, EN, FR and ES.

Before

[music]

SPEAKER 1: you comin or what

[foreign language]

42 cps · no context · no identity

After

♪ tense synth pulse builds ♪

DEV: You comin' or what?

[speaking Portuguese] Não foi culpa dele.

16 cps · sound as information

Metrics

Support agents served by restructured content30k+
Reduction in failed information retrieval67%
Subtitle entries annotated and reviewed10k+
SDH compliance on delivered titles100%

Case 03 · UI Localization

Adobe Creative Cloud Localization

Broken and inconsistent UI strings across global builds were confusing international users. I combined string-level localization with UX testing and a visual feedback loop that engineers could actually act on.

LocalizationUI/UX ConsistencyBeta TestingmemoQLQA

Problem

Truncated, untranslated and inconsistent strings across menus, buttons and tooltips.

Issues reported in prose — slow to reproduce, slower to fix.

Solution

50K+ words localized against a controlled glossary and screenshot context.

UX testing split functional bugs from linguistic ones, routed to the right team.

Annotated screenshots with severity, string ID and expected output.

Before

Chaotic UI · inconsistent labels · raw code exposed

After

Identify potential UX flaws.

Case 04 · Automation

Python Automation for SDH Metadata

Hours of manual SRT formatting were slowing every delivery. A small Python pipeline now parses, validates and structures SDH metadata in seconds.

PythonAutomationSDHWorkflow Design

Problem

Every subtitle file needed manual cleanup: numbering, timecodes, line breaks, tags.

Inconsistent formatting between files and between linguists.

Solution

Python script parses SRT entries, validates timecodes and reading rate.

Structured metadata output feeds QA and delivery without manual steps.

Shared with the team — no Python knowledge needed to run it.

Before

1 00:00:01, 000 --> 00:00:03.000 [MUSIC]

hello WORLD .<i>test</i> 57cps

3 00:00:2,500 → 00:00:04,00

Broken timecodes · mixed separators

After

1 · 00:00:01,000 → 00:00:03,000 · ♪ music ♪

2 · 00:00:03,100 → 00:00:05,000 · Hello, world.

3 · 00:00:05,100 → 00:00:07,200 · 16 cps ✓

Validated · structured · consistent
